# SaaS 메인 전환 플랜 (2026-04-23)

> PDF 매출 포기하지 않으면서 SaaS로 무게중심 이동.
> 품질 우선, 일정 없음, 주 10~20시간 기준.

## 0. 사용자 결정사항 (Interview 결과)

| 항목 | 결정 |
|---|---|

## 1. 전환 전략 요약

### 핵심 포지션
```
SaaS (메인) ═══════════════════════════════════════════════
  └ 버디민턴 배드민턴 동호회 관리 플랫폼
  └ Free / Pro / Team 요금제
  └ 본인 동호회 테스트베드

PDF (구색) ────────────────────────────────────────────────
  └ Toss 계약 유지용으로만 존재
  └ Footer 링크로만 접근 가능
  └ 판매 노력 투입 최소
```

### 트레이드오프
- ❌ **포기:** 블로그 SEO·뉴스레터 자동화·라켓 도감 유지·PLF 이메일 시퀀스
- ✅ **집중:** SaaS 코어 품질·카카오 OAuth·통합 `/product` 페이지·본인 동호회 실사용

## 2. 현재 상태 분석 (v2-main)

### ✅ 이미 완성된 것
| 영역 | 파일/경로 |
|---|---|
| 랜딩 | `/` (Hero·고통 포인트·6기능·요금제·타겟·CTA·PDF 섹션) |
| 기능 소개 | `/features` |
| 요금제 | `/pricing` |
| 데모 진입 | `/demo` → `/club/demo-1` |
| 카카오 로그인 UI | `/login` + `KakaoLoginButton` + `loginWithKakao` server action |
| OAuth 콜백 핸들러 | `/auth/callback` |
| 클럽 코어 | `/club/home`, `/club/create`, `/club/[id]/{gameboard,ranking,members,notices,finance,settings,import,join-requests}` |
| 온보딩 | `/club/onboard`, `/join/[code]` |
| SHOP | `/shop`, `/shop/starter-guide`, `/shop/starter-guide/order` |
| 결제 결과 | `/pdf/success`, `/pdf/fail` |
| Toss 연동 | `/api/payments/toss/confirm`, `OrderForm` 컴포넌트 |
| 환불정책 | `/policy/refund` |
| 법적 페이지 | `/terms`, `/privacy` |
| 데모 데이터 | `DEMO_CLUBS` (1개), `DEMO_MEMBERS`, `DEMO_NOTICES` |

### ❌ 빠진 것 / 고쳐야 할 것
| 영역 | 문제 |
|---|---|
| **카카오 OAuth** | 버튼 눌러도 동작 안 함 (Supabase Provider 설정 or redirect URI 미등록 의심) |
| **`/product` 통합 페이지** | 존재 안 함 |
| **`/features`, `/pricing`** | 삭제 + 리다이렉트 필요 (`/product`로) |
| **`/blog` 골격** | 존재 안 함 |
| **`/my/profile`** | 존재 안 함 |
| **`/contact`, `/faq`** | 존재 안 함 |
| **v1 잔재 `/business`** | 존재, 용도 불명 |
| **v1 잔재 경로들** | `/club/demo`, `/club/login`, `/club/new`, `/dashboard` 확인 필요 |
| **Header에 SHOP 링크** | 제거 필요 (Footer만 유지) |
| **랜딩 PDF 섹션** | 축소 또는 제거 필요 (SHOP 네비 제거 일관성) |
| **Vercel 프로덕션 상태** | v1 라켓 플랫폼 배포 중 → v2-main으로 전면 교체 |
| **프로덕션 환경변수** | Kakao 키·Toss 키·Supabase 키 검증 필요 |
| **카카오 Redirect URI** | `https://birdieminton.com/auth/callback` 등록 확인 |

## 3. Sprint 계획 (주 10~20h 기준)

> **모든 Sprint 시작 시점에 세부 설계 질문을 사용자에게 다시 드립니다.**
> 사용자 지시: "설계할 때 무조건 나에게 물어봐"

### Sprint 1 — 카카오 OAuth 복구 (1주, 8~12h)
**목표:** SaaS 전체의 전제가 되는 로그인을 먼저 살림

| # | 작업 | 예상 시간 |
|---|---|---:|
| 1.1 | Supabase Auth 대시보드에서 Kakao Provider 활성 상태 확인 | 0.5h |
| 1.2 | Kakao 개발자 센터에서 Redirect URI 등록 확인 (`localhost` + `birdieminton.com`) | 0.5h |
| 1.3 | 로컬에서 `/login` → 카카오 → 콜백 전체 플로우 디버깅 | 3~5h |
| 1.4 | `ensureClubUser` 함수 동작 검증 (users 테이블 upsert) | 1h |
| 1.5 | `/auth/callback` 리다이렉트 분기 검증 (신규·기존 유저) | 1h |
| 1.6 | 본인 카카오 계정으로 로그인 → `/club/home` 도달 확인 | 0.5h |
| 1.7 | 로그아웃 플로우 검증 | 0.5h |

**완료 기준:** 로컬에서 카카오 로그인 ↔ 로그아웃 완전 동작.

**⚠️ Sprint 1 시작 전 질문할 것:**
- 카카오 개발자 센터 Redirect URI 현재 등록 목록 공유
